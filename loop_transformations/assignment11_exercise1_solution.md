# Assignment 11 - Exercise 1: Strength Reduction

## About the exercise

The goal of this exercise is to optimize small scalar code fragments by replacing expensive operations with cheaper ones, when this can be done without changing the meaning of the program.

This is called **strength reduction**.

The main idea is to look at the original code, apply a manual transformation, and then compare it with the assembly generated by `gcc -O3`.

---

## When should strength reduction be applied?

Strength reduction should be used when a costly operation can be replaced by a cheaper equivalent operation, for example:

- multiplication by a power of two → shift
- repeated multiplication inside a loop → incrementing an index
- division by a constant → multiplication by the reciprocal, if allowed
- loop-invariant computation → move it outside the loop
- multiplication by `-1` for floating-point numbers → negation

It is worth applying when the cheaper operations cost less than the original operation and the transformation preserves the required semantics for the target type.

---

## a) `unsigned c2 = 32 * c1;`

### Manual transformation
```c
unsigned c2 = c1 << 5;
```

### Why?
`32` is `2^5`, so multiplying by 32 is the same as shifting left by 5 bits.

### GCC `-O3`
GCC already turns the multiplication into a shift:

```asm
sal esi, 5
```

So the compiler applies the same optimization automatically.

---

## b) `unsigned c2 = 15 * c1;`

### Manual transformation
```c
unsigned c2 = (c1 << 4) - c1;
```

### Why?
`15 = 16 - 1`, so we can compute `15 * c1` using one shift and one subtraction.

### GCC `-O3`
GCC also strength-reduces this expression:

```asm
sal esi, 4
sub esi, edi
```

So it uses a shift and subtract instead of a multiply.

---

## c) `unsigned c2 = 96 * c1;`

### Manual transformation
```c
unsigned c2 = (c1 << 6) + (c1 << 5);
```

### Why?
`96 = 64 + 32`, so the multiplication can be replaced by two shifts and one addition.

### GCC `-O3`
GCC uses a different but equivalent optimization:

```asm
lea esi, [rdi+rdi*2]
sal esi, 5
```

So GCC does not use exactly the same expression as my manual transformation, but it still removes the direct multiplication and replaces it with cheaper operations.

---

## d) `unsigned c2 = 0.125 * c1;`

### Manual transformation
```c
unsigned c2 = c1 >> 3;
```

### Why?
`0.125 = 1/8`, and dividing by 8 is equivalent to shifting right by 3 for unsigned integer values.

### GCC `-O3`
GCC keeps the computation in floating-point form and uses conversion plus floating-point multiply:

```asm
cvtsi2sdq xmm0, rdi
mulsd xmm0, QWORD PTR .LC3[rip]
cvttsd2si rsi, xmm0
```

So GCC does not use the same integer shift form here, because the source expression is written as a floating-point multiplication.

---

## e)
```c
unsigned sum_fifth = 0;
for (int i = 0; i < N / 5; ++i) {
    sum_fifth += a[5 * i];
}
```

### Manual transformation
```c
unsigned sum_fifth = 0;
for (int i = 0, idx = 0; i < N / 5; ++i, idx += 5) {
    sum_fifth += a[idx];
}
```

### Why?
Instead of computing `5 * i` in every iteration, the code can just keep a running index that increases by 5.

### GCC `-O3`
GCC performs the same kind of loop strength reduction. In the assembly, it increments the pointer by 20 bytes each iteration instead of recomputing `5 * i`:

```asm
add rdi, 20
```

This is the same optimization in a more low-level form.

---

## f)
```c
for (int i = 0; i < N; ++i) {
    a[i] += i / 5.3;
}
```

### Manual transformation
```c
double factor = 1.0 / 5.3;
for (int i = 0; i < N; ++i) {
    a[i] += i * factor;
}
```

### Why?
The divisor `5.3` is constant, so the reciprocal can be computed once outside the loop. That replaces repeated division with multiplication by a constant.

### GCC `-O3`
GCC produces a much more optimized version here. It vectorizes the loop and uses packed SIMD instructions. In the original version it performs vectorized floating-point division, while in the transformed version it uses vectorized multiplication by the reciprocal constant.

So GCC not only applies strength reduction, but also combines it with vectorization.

---

## g) `float c2 = -1 * c1;`

### Manual transformation
```c
float c2 = -c1;
```

### Why?
For IEEE 754 floating-point numbers, negation usually just flips the sign bit. That is cheaper than a multiply.

### GCC `-O3`
GCC already optimizes this to sign-bit flipping:

```asm
xorps xmm0, XMMWORD PTR .LC18[rip]
```

So GCC replaces multiplication by `-1` with a cheaper negation operation.

---

## What I observed from the assembly

In most cases, GCC `-O3` already applies the same or a very similar optimization automatically.

- For `a`, `b`, and `g`, GCC uses the expected cheap operations directly.
- For `c`, GCC chooses a different but still valid arithmetic sequence.
- For `d`, GCC keeps floating-point conversion and multiplication, because the source is written as a floating-point expression.
- For `e`, GCC transforms the indexed access into pointer stepping.
- For `f`, GCC applies a stronger optimization and vectorizes the loop.
